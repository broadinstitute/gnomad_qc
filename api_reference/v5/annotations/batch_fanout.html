gnomad_qc.v5.annotations.batch_fanout

Hail Batch relay fan-out for the v5 annotation scripts.

A Query-on-Batch run has one driver, and a driver crash loses everything it was computing. The scripts therefore cut the genome into chunks and run each chunk from its own small, non-spot Batch job (a “relay”) that starts a QoB driver inside its container. A crash then costs one chunk, and a rerun skips the chunks that already have a _SUCCESS marker. The orchestrator that submits the relays never starts Hail.

Chunk outputs are stored under a hash of the chunk layout. The layout is sampled without a fixed seed, so each regeneration moves the cut points, and a chunk left behind by an older layout must not be taken for a finished chunk of the new one.

gnomad_qc.v5.annotations.batch_fanout.build_setup_command(commit, gcp_billing_project='broad-mpg-gnomad', methods_branch='main', hail_version=None)[source]

Return the shell prefix every relay runs before the script.

Both repos change faster than the image, so the relay downloads them at the pinned commit and branch when it starts. The Hail config file sets the Batch billing project and scratch directory for the nested QoB driver, and together with the quota_project_id patch gives Hail’s GCS client a requester-pays project, which a bare container has no gcloud config to supply.

Parameters:

  • commit (str) – gnomad_qc commit to check out.

  • gcp_billing_project (str) – Requester-pays project.

  • methods_branch (str) – gnomad_methods branch or commit to check out.

  • hail_version (Optional[str]) – If set, reinstall this Hail version in the container; otherwise the image’s Hail is used. The relay’s Python Hail sets the QoB JAR, so this pins everything. WARNING: the pin is also a floor for every HT the pipeline reads. Hail’s table format is not backward compatible, so lowering the pin without rewriting the input HTs breaks the fan-out.

Return type:

str

Returns:

Shell command string ending in a newline.

gnomad_qc.v5.annotations.batch_fanout.submit_relay_batch(batch_image, backend_kwargs, batch_name, job_specs, log_label, *, dry_run)[source]

Submit one Hail Batch of relay jobs and wait for it.

Relays are non-spot because a preempted relay leaves the QoB batch it was waiting on running with nobody to collect it. For the same reason callers normally ask for one attempt: a Batch retry cannot cancel that orphaned batch and would run alongside it.

  • backend_kwargs (Dict[str, str]) – kwargs for hb.ServiceBackend.

  • batch_name (str) – Hail Batch name.

  • job_specs (Sequence[RelayJobSpec]) – Jobs to submit; nothing is submitted when empty.

  • log_label (str) – Noun for log messages (“chunk”, “merge”).

  • dry_run (bool) – Validate the batch without running it.

Return type:

Optional[int]

Returns:

Batch id, or None when nothing ran.

gnomad_qc.v5.annotations.batch_fanout.dispatch_in_waves(pending, wave_size, submit_wave, present_indices, *, dry_run, on_wave_complete=None, retry_passes=0)[source]

Submit pending chunks in sequential waves and report the ones that did not land.

Waves cap how many relays, and so how many nested QoB drivers, run at once. A batch run does not raise when a job fails, so the chunk directory is listed again after each wave to find the chunks that did not land.

After the last wave, the chunks still missing are re-dispatched up to retry_passes times. This is safe where Batch-level attempts are not: by the time a pass runs, every relay from the previous dispatch has exited, so a re-dispatch cannot race a live relay’s inner QoB batch.

Parameters:

  • pending (Sequence[int]) – Chunk indices to dispatch.

  • wave_size (int) – Chunks per wave; <= 0 means one wave.

  • submit_wave (Callable[[List[int], Optional[str]], Optional[int]]) – Submits one wave and returns its batch id. It must honor the dry run itself (pass dry_run on to submit_relay_batch()); this function only stops after the first wave. Retry passes get the labels retry1, retry2, …

  • present_indices (Callable[[], Set[int]]) – Lists the chunk indices with _SUCCESS.

  • dry_run (bool) – Stop after the first wave without checking its outputs.

  • on_wave_complete (Optional[Callable[[List[int], List[Dict[str, Any]]], None]]) – Called after each wave and each retry pass with the failed indices and wave records so far, e.g. to rewrite the failed-chunk manifest so it survives an orchestrator death. Not called on a dry run. The lists are this function’s live accumulators: read them, do not keep or change them.

  • retry_passes (int) – Re-dispatch passes for missing chunks after the waves.

Return type:

Tuple[List[int], List[Dict[str, Any]]]

Returns:

(failed indices, wave records); the failed list is what is still missing after the last retry pass. Both are empty when nothing was pending and on a dry run, so a caller must check dry_run before treating an empty failed list as “every chunk landed”.

gnomad_qc.v5.annotations.batch_fanout.orchestrate_tree_merge(inputs, final_output_path, group_path_fn, merge_group_size, overwrite, final_coalesce_to, batch_prefix, job_prefix, setup_cmd, script, common_flags, merge_cpu, merge_memory, merge_storage, final_merge_storage, submit, attempts=1)[source]

Union inputs into final_output_path with a tree of relay merge jobs.

With thousands of chunks, one job that unions everything would need a huge input list and too much memory, so the merge is a tree. Each level groups its inputs merge_group_size at a time and submits one --run-merge job per group; a group whose HT already exists is skipped unless overwrite is set. The last level is a single job that writes the final HT, and it always runs and overwrites, so a caller that wants to keep an existing final HT checks for it before calling.

Parameters:

  • inputs (Sequence[str]) – Chunk HT paths, in order.

  • final_output_path (str) – Final HT path.

  • group_path_fn (Callable[[int, int], str]) – (level, group_idx) -> intermediate HT path.

  • merge_group_size (int) – Inputs per merge job.

  • overwrite (bool) – Recompute intermediate groups that already exist.

  • final_coalesce_to (Optional[int]) – --merge-coalesce-to for the final job, or None.

  • batch_prefix (str) – Batch name prefix; level and final are appended.

  • job_prefix (str) – Job name prefix.

  • setup_cmd (str) – Relay shell prefix from build_setup_command().

  • script (str) – Script command inside the relay container.

  • common_flags (str) – Flags appended to every --run-merge command.

  • merge_cpu (float) – CPU per merge job.

  • merge_memory (str) – Memory class per merge job.

  • merge_storage (str) – Storage per intermediate merge job.

  • final_merge_storage (str) – Storage for the final merge job.

  • submit (Callable[[str, List[RelayJobSpec], str], Optional[int]]) – (batch_name, job_specs, log_label) -> batch id.

  • attempts (int) – Batch attempts per merge job. Default 1.

Return type:

None

Returns:

None.
